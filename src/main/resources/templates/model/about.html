About Our Model

How the AI prediction engine actually works

🤖 Gradient Boosting · 6 position models

Overview

We train one GradientBoostingRegressor (scikit-learn) per position — QB, RB, WR, TE, K, DST — rather than a single model for every player. Each position scores fantasy points differently, so keeping the models separate lets each one learn the stat patterns that actually matter for that position instead of averaging them all together.

What it predicts: a player's total PPR fantasy points for the next season, using their most recently completed season's stats as input.

Hyperparameters (same for every position): n_estimators=200, max_depth=3, learning_rate=0.05, subsample=0.8. Shallow trees (depth 3) and a slow learning rate keep the model from overfitting to single standout seasons, which matters given how much year-to-year variance fantasy football has.

Training Target

The target is Sleeper's pts_ppr value — the PPR-scored fantasy total Sleeper already computes server-side from raw box scores. We store that number directly as total_points rather than re-deriving it from raw stats, so the model is always learning to predict the exact scoring system fantasy managers see.

Metrics the Model Trains On

Every metric below is computed from historical Sleeper season/weekly stats and ESPN schedule data. Features are grouped by what they capture.

Metric What it Captures Used By
Core Productivity
total_points Prior season's PPR fantasy points — the single strongest predictor of future output. All positions
points_per_game Total points ÷ games played. Normalizes production for players who missed time. All positions
games_played Availability / durability signal, counted from weekly stat rows. All positions
Age Curve
age, age_sq Player's age (as of Sept 1 of that season, computed from birth date) and its square, letting the model fit a curved (rise-peak-decline) aging pattern instead of a straight line. QB, RB, WR, TE, K (not DST — team unit, no single age)
Trend / Momentum (Two-Season Lag)
prev2_total_points, prev2_points_per_game Season N-2 stats (two seasons before the target), giving the model a second data point to judge direction, not just level. All positions
pts_delta Change in total points vs. two seasons ago. Zeroed out for rookies (see has_prev2) so it never fakes an "improvement." All positions
has_prev2 1 if the player has data from two seasons ago, 0 if this is only their second pro season. Flags rookies for the blending guardrail below. All positions
Weekly Consistency / Volatility
weekly_pts_std Standard deviation of weekly PPR scores — a boom/bust indicator. High = volatile week to week. All positions
floor / ceiling Average of the player's worst 4 and best 4 weeks — captures realistic downside/upside beyond a single-number average. All positions
games_over_10 / games_over_20 Count of weeks scoring above 10 / 20 fantasy points — reliability thresholds fantasy managers actually care about. QB, RB, WR, TE (K uses none, DST uses none)
Schedule Strength
opp_pts_allowed Average points the player's opponents allowed to that position, computed from ESPN matchup data. Higher = easier schedule faced. Defaults to 0.0 when opponent data hasn't been backfilled for a season. QB, RB, WR, TE, K (not DST)

passing_yds, passing_td, passing_int Raw passing production. QB
rushing_yds, rushing_td Raw rushing production. QB, RB
targets, receiving_rec, receiving_yds, receiving_td, reception_pct Receiving volume and efficiency (catches ÷ targets). RB, WR, TE
fg_made, pat_made, pat_missed Kicking volume and reliability. K
def_sacks, def_ints, def_fum_rec, def_td, def_safeties, def_blocked_kicks, pts_allowed Team defensive/special-teams production and points surrendered. DST

Guardrails Applied After Prediction

The raw model output isn't shown as-is — two rules run afterward in serve.py to correct known failure modes.

🌱
Rookie Blending

Players entering only their second season (has_prev2 = 0) have no trend context, so the model tends to over-extrapolate from one data point. Their projection is blended 55% model output / 45% that season's position-wide average among established veterans.

🧢
Improvement Cap

No player's projection can exceed 1.40× their prior season's total points. This still allows genuine breakout seasons while preventing the model from projecting runaway, unrealistic jumps.

🩹
Status Discount

Players currently marked Injured Reserve, PUP, Suspended, or Inactive on Sleeper get a modest haircut (roughly 10–25% depending on severity). This is a soft, prediction-time signal only — Sleeper only exposes a player's current roster status, not a history of it, so status is never fed into training the way box-score stats are.

Measured Accuracy

Accuracy is measured with walk-forward validation — the model trains only on past seasons and is tested on a season it has never seen, mimicking how it's actually used. We deliberately avoid random k-fold cross-validation here since shuffling seasons randomly would leak future information into training and produce an overly optimistic score.

Where the Data Comes From

Season and weekly stats are pulled from the free Sleeper API (no key required), covering 2020–2025. Opponent matchups per week come from ESPN's public scoreboard API, used only to compute the opp_pts_allowed schedule-strength feature — team codes between the two sources are normalized (e.g. Sleeper's "LVR" → "LV", ESPN's "WSH" → "WAS") so players and opponents match up correctly across systems.

Training data is built as (season N stats + season N-1 trend) → (season N+1 actual points) pairs, so a model trained today learns from every 2020→21, 2021→22 … 2024→25 transition in the data at once.

Known Limitations

The model currently does not account for:

  • Historical injury data — Sleeper only exposes a player's status as of right now, not per-season history, so a player's current status only informs a soft discount at prediction time (see Status Discount above), not the trained model itself
  • Target share, snap share, or backfield/depth-chart competition
  • Coaching or scheme changes (new OC/HC, run-first vs. pass-first shifts)
  • Draft capital, ADP, or market consensus
  • Teammate movement (e.g. a WR1 leaving in free agency)
  • League-wide scoring inflation/deflation across seasons
